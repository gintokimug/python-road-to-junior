
> [!abstract] Теория
> Оценка сложности работы алгоритмов
> Буква **`n`** в формулах всегда означает **размер данных** (длину списка, количество строк в БД).
> - скорость работы программы по  числу арифметических действий
> - скорость работы программы по её фактическому времени выполнения 
> Скорость работы программы как верхняя граница динамики измерения вычислительной сложности алгоритма в зависимости от размера входных данных  ( Big O)
> 
> ❓**О(1) Константная сложность**  - для команд, выполняющихся за фиксированное время
> - Время выполнения алгоритма **ВООБЩЕ НЕ ЗАВИСИТ** от количества данных (`n`). Программе нужно сделать ровно 1 (или фиксированное количество) шагов, чтобы выдать результат. 
> - В математике Big O мы отбрасываем константы (фиксированные цифры).
> - O(1) — это не обязательно одна строчка. O(1) значит лишь то, что в коде **нет циклов, зависящих от размера входных данных n**.
>
>
> >[!Пример]
> >1. **Доступ к элементу списка по индексу** 
> >   Компьютер знает адрес начала списка в памяти и просто "прыгает" на нужный шаг. Ему неважно, в списке 5 элементов или 5 миллионов.  
> >   
> >   `def get_first_element(my_list):`
> >    `return my_list[0]` # Это всегда O(1)  
> >    
> > 2. **Доступ к значению словаря по ключу**  
> >Словари (dict) под капотом используют хэш-таблицы. Питон мгновенно вычисляет математический хэш ключа и сразу прыгает в нужную ячейку памяти.
>>
>>
>>
>>`def get_user_role(user_dict):`
>>    `return user_dict["role"]`  # Это всегда O(1)
>>    
>>3. **Проверка длины списка/строки**
>>  Питон хранит длину списка как отдельную цифру-свойство. Ему не нужно считать элементы.
>>  
>>`length = len(my_list)` # O(1)
> 
>

> ❓**О(log n) Логарифмическая сложность** - для алгоритмов с линейной сложностью (например, перебор элементов в цикле)
> - С каждым шагом алгоритма объем данных, который нужно проверить, **уменьшается в 2 раза**.
> - **Основание логарифма.** В программировании под $\log n$ всегда подразумевается логарифм по основанию **2** (так как мы делим пополам).
> Cамый явный пример бинарный поиск:
> > [!Note] Пример
> > def binary_search(sorted_list, target):
> >    low = 0
> >    high = len(sorted_list) - 1
> >
> >    while low <= high:
> >        mid = (low + high) // 2
> >        guess = sorted_list[mid]
> >        
> > if guess == target:
> >            return mid
> >        if guess > target:
> >            high = mid - 1 # Отсекаем правую часть
> >        else:
> >            low = mid + 1  # Отсекаем левую часть
> >    return None
> > 
>
>
>❓**О(n^2) Квадратическая сложность** - для алгоритмов с квадратичной сложностью ( вложенные циклы) 
> - время выполнения программы растет **пропорционально** количеству данных.
> Примеры O(n) :
> 
>
> > [!Note] Пример 1.Обычный цикл **for**
> > ```
> > def find_element(my_list, target):
> > 	   for item in my_list:
> >        if item == target:
> >            return True
> >    return False
> > ```
> 
> >[!Note] Пример 2. Встроенные функции агрегации **(sum, max, min)**  
Питон не маг. Чтобы найти сумму или максимум в неупорядоченном списке, ему физически нужно просмотреть каждый элемент. Под капотом этих функций спрятан обычный цикл, зависящий от n.
>>```
>>numbers = [5, 2, 9, 1, 7]
total = sum(numbers)  # Это O(n)
biggest = max(numbers) # Это тоже O(n)
>>```
>

>>Когда ты пишешь if x in my_list, Питон под капотом запускает цикл и сравнивает x с каждым элементом списка по очереди.
>>```
 if "apple" in my_list:  # Python идет по списку и сравнивает каждый элемент
>
>
> >[!Note] Пример 4.Скрытое O(n): методы списка
> >
> > Методы списков
> >
> >- `list.index(x)` — ищет элемент с начала до конца. $O(n)$.
> >    
> >- `list.count(x)` — считает, сколько раз встречается `x` (проходит весь список). $O(n)$.
> >    
> >- `list.insert(0, x)` — вставка в начало. Python приходится сдвигать все остальные элементы вправо. $O(n)$.
> >    
> >- `list.pop(0)` или `del list[0]` — удаление из начала. То же самое: все элементы сдвигаются влево. $O(n)$.
> 
> > [!Note] Пример 5. Скрытое O(n): срезы 
> > Создание среза — это **$O(k)$**, где $k$ — длина среза. Если срез почти во весь список, это фактически $O(n)$.
> >```
> > new_list = my_list[10:100]  # Копирование элементов в новый список
>
> > [!Note] Пример 6. Скрытое O(n): строковые операции
> > - `string.replace('a', 'b')` — нужно пройтись по всей строке. $O(n)$.
> >    
> >- `char in string` — поиск символа в строке. $O(n)$.
