
> [!abstract] Теория
> Оценка сложности работы алгоритмов
> Буква **`n`** в формулах всегда означает **размер данных** (длину списка, количество строк в БД).
> - скорость работы программы по  числу арифметических действий
> - скорость работы программы по её фактическому времени выполнения 
> Скорость работы программы как верхняя граница динамики измерения вычислительной сложности алгоритма в зависимости от размера входных данных  ( Big O)
> 
> ❓**О(1) Константная сложность**  - для команд, выполняющихся за фиксированное время
> - Время выполнения алгоритма **ВООБЩЕ НЕ ЗАВИСИТ** от количества данных (`n`). Программе нужно сделать ровно 1 (или фиксированное количество) шагов, чтобы выдать результат. 
> - В математике Big O мы отбрасываем константы (фиксированные цифры).
> - O(1) — это не обязательно одна строчка. O(1) значит лишь то, что в коде **нет циклов, зависящих от размера входных данных n**.
>
>
> >[!Пример]
> >1. **Доступ к элементу списка по индексу** 
> >   Компьютер знает адрес начала списка в памяти и просто "прыгает" на нужный шаг. Ему неважно, в списке 5 элементов или 5 миллионов.  
> >   
> >   `def get_first_element(my_list):`
> >    `return my_list[0]` # Это всегда O(1)  
> >    
> > 2. **Доступ к значению словаря по ключу**

> >
> >
> >
> >`def get_user_role(user_dict):`
> >    `return user_dict["role"]`  # Это всегда O(1)
> >    
> >1. **Проверка длины списка/строки**
> >  Питон хранит длину списка как отдельную цифру-свойство. Ему не нужно считать  элементы.
>>  
>>`length = len(my_list)` # O(1)

> ❓**О(log n) Логарифмическая сложность** - для алгоритмов с линейной сложностью (например, перебор элементов в цикле)
> - С каждым шагом алгоритма объем данных, который нужно проверить, **уменьшается в 2 раза**.
> - **Основание логарифма.** В программировании под $\log n$ всегда подразумевается логарифм по основанию **2** (так как мы делим пополам).
> Cамый явный пример бинарный поиск:
> > [!Note] Пример
> > ```python
> > def binary_search(sorted_list, target):
> >    low = 0
> >    high = len(sorted_list) - 1
> >
> >    while low <= high:
> >        mid = (low + high) // 2
> >        guess = sorted_list[mid]
> >        
> > if guess == target:
> >            return mid
> >        if guess > target:
> >            high = mid - 1 # Отсекаем правую часть
> >        else:
> >            low = mid + 1  # Отсекаем левую часть
> >    return None
> > ```
> > 
>
>

> ❓**О(n log n) Линейно-логарифмическая сложность** - программа делает операцию `O(log n)` (например, делит массив пополам) ровно `n` раз (для каждого элемента).
> -Сложность $O(n \log n)$ обычно возникает в алгоритмах, которые работают по такой схеме:
>
>1. **Разделение ($\log n$):** Мы режем задачу пополам снова и снова, пока не дойдем до элементарных кусочков (как в бинарном поиске).
>    
> 2. **Сборка ($n$):** На каждом этапе деления нам нужно пройтись по всем $n$ элементам, чтобы сравнить их или склеить обратно.
> - считается эффективным классом сложности, особенно при работе с большими объёмами данных
>- отражает идею «делить и властвовать»: задача многократно разделяется на мелкие подзадачи, которые решаются независимо, а затем результаты объединяются.
>  
> > [!Note] пример Сортировка слиянием
> >```python
> >def merge_sort(arr):
> >	if len(arr) <= 1:
> >	return arr
> >	
> >	# Рубим пополам 
> >	mid = len(arr) // 2
> >	left_half = arr[:mid]
> >	right_half = arr[mid:]
> >	
> >	# Рекурсия (сортировка половинок)
> >	Функция будет вызывать саму себя, пока не дойдёт до 1 элемента 
> >	left_sorted = merge_sort(left_half)
> > 	right_sorted = merge_sort(right_half)
> >	
> >	# Склейка (функция- помощник)
> >	return merge(left_sorted,right_sorted)
> >	
> >	def merge( left, right):
> >	 
> >	result = [] # для результата
> >	i = 0 # индекс левого списка
> >	j = 0 # индекса правого списка 
> >	
> >	# пока мы не дошли до конца хотя бы одного из списков
> >	while i < len(left) and j < len(right):
> >		if left[i] < right[j]: 
> >			result.append(left[i]) # левый меньше, добавляем в результ
> >			i += 1 # сдвиг левого указателя вперёд 
> >
> >		else:
> >			result.append(right[j]) # правый меньше, кладём его 
> >			j += 1 # сдвигаем правый указатель вперёд 
> >	result.extend(left[i:])
> >	result.extend(right[j:])
> >	return result 
> >	
> >print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
> >			
> >```
>
> > [!Note] пример быстрая сортировка
> > 
> >
> >
> >```python
> >def quick_sort(arr):
> >	if len(arr) <= 1:
> >		return arr
> >	
> >	# выбираем опорный элемент Pivot
> >	# Можно брать любой, для надёжности берётся из середины
> >	pivot = arr[len(arr) // 2]
> >	
> >	# Разделение - линейная работа О(n)
> >	# Проход по списку и раскидка элементов
> >	left = [x for x in arr if x < pivot]
> >	middle = [x for x in arr if x == pivot]
> >	right = [x for x in arr in x > pivot]
> >	
> >	# Рекурсия и склейка 
> >	# функция сортирует элементы и складывает 
> >	return quick_sort(left) + middle + quick_sort(right)
> >print(quick_sort([5, 2, 9, 1, 5, 6]))

>❓ O(n^2) Квадратичная сложность алгоритм, время выполнения которого растет в квадрате относительно количества данных.
>Если данных станет в 10 раз больше, программа будет работать в **100 раз дольше**. Если данных станет в 1000 раз больше — время работы увеличится в **миллион раз**.

> > [!Note] Пример 1. Вложенный список **for**
> > Если ты видишь цикл `for` внутри другого цикла `for`, которые идут по одним и тем же данным — это 100% квадратичная сложность. 
> > ```python 
> > def print_all_pairs(items):
> > 	 for i in items: # Внешний цикл O(n) 
> > 		 for j in items: # Внутренний цикл O(n) 
> > 			 print(i, j) # n * n = O(n²)
>
>
> > [!Note] Пример 2. Bubble Sort 
> > Это самая простая, но и самая неэффективная сортировка. Она сравнивает соседние элементы и «проталкивает» самый большой в конец, и так много-много раз.
> > 
> > ```python
> > def bubble_sort(arr):
> >  n = len(arr)
> >    for i in range(n):              # Проходим по всему списку n раз
> >        for j in range(0, n-i-1):   # Внутри снова проходим по списку
> >            if arr[j] > arr[j+1]:
> >                # Меняем местами
> >                arr[j], arr[j+1] = arr[j+1], arr[j]
> >    return arr
> > ```
> >
> 
> > [!Note] Пример 3. Скрытые квадраты
> > ```python
> > def find_duplicates(arr):
> >    duplicates = []
> >    for x in arr:             # Цикл O(n)
> >        if arr.count(x) > 1:  # СКРЫТЫЙ цикл O(n) внутри!
> >            duplicates.append(x)
> >    return duplicates
> > ```
> > 
> **Как избежать:**
>
>- Вместо вложенного поиска используй **словари (`dict`)** или **множества (`set`)**. Проверка `if x in my_set` — это $O(1)$, что превратит твой $O(n^2)$ в $O(n)$.
>    
>- Если нужно сортировать — используй встроенный `.sort()`, он работает за $O(n \log n)$.
