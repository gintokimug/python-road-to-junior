
В прошлом уроке мы научились искать конкретную задачу по её ID: /tasks/1.  
Но что, если мы хотим не **одну** задачу, а **список**, но с определенными условиями?

Например:

- «Покажи только выполненные задачи».
    
- «Покажи задачи, созданные сегодня».
    
- «Покажи первые 10 задач, а не все миллион».
    

Для таких целей в HTTP используются **Query Parameters (Параметры запроса)**.

### Что это такое?

Вы сталкиваетесь с ними каждый день. Вспомните, когда вы ищете что-то в Google или на YouTube. Вы вводите слово, нажимаете Enter, и адресная строка меняется.

Она выглядит примерно так:  
https://google.com/search?q=fastapi&source=desktop

Всё, что идет **после вопросительного знака ?**, называется **Строкой запроса (Query String)**.

### Анатомия строки запроса

Строка запроса — это набор пар «Ключ = Значение».

1. **? (Вопросительный знак)** — Это разделитель. Он говорит серверу: "Адрес закончился, дальше идут настройки".
    
2. **key=value** — Сами данные. Например, page=2 или sort=price.
    
3. **& (Амперсанд)** — Используется, если параметров несколько. Он склеивает их вместе.
    

**Пример:**  
http://my-first-api.com/items?skip=0&limit=10&sort_by=name

Здесь мы передаем серверу сразу три параметра:

1. skip равен 0
    
2. limit равен 10
    
3. sort_by равен name
    

### Path vs Query: Когда и что использовать?

Новички часто путаются: "Когда передавать ID через слэш /items/5, а когда через вопрос /items?id=5?"

В REST API есть негласное правило этикета:

|   |   |   |   |
|---|---|---|---|
|Тип параметра|Пример|Назначение|Аналогия|
|**Path (Путь)**|/book/42|**Идентификация ресурса.** Обязательная часть. Без этого параметра страницы не существует.|"Дайте мне книгу с полки №42"|
|**Query (Запрос)**|/books?author=Tolkin|**Сортировка / Фильтрация.** Опциональная часть. Если убрать параметры, список просто вернется целиком или в стандартном виде.|"Дайте мне любые книги Толкиена"|

### Резюме

- Параметры пути (/tasks/{id}) — это часть **адреса**.
    
- Параметры запроса (/tasks?completed=true) — это **настройки**.


# Магия объявления параметров

В других фреймворках вам часто нужно лезть в специальный объект request, искать там словарь с аргументами и вручную их доставать.  
В FastAPI всё работает через **аргументы функции**.

У вас может возникнуть вопрос: "У меня есть функция def func(id, limit). Как FastAPI поймет, что id — это часть пути, а limit — это параметр запроса?"

### Главное правило FastAPI

Фреймворк смотрит на две вещи:

1. Строку пути в декораторе (@app.get(...)).
    
2. Аргументы вашей функции.
    

И делает простой вывод:

- Если имя аргумента **ЕСТЬ** в пути в фигурных скобках {} — это **Path Parameter** (обязательный).
    
- Если имя аргумента **ЕСТЬ** в функции, но **НЕТ** в пути — это автоматически **Query Parameter**.
    

### Пишем код

Давайте реализуем классический пример — **Пагинацию** (постраничный вывод). Мы хотим, чтобы клиент мог сказать: "Дай мне 10 задач, пропустив первые 20".

Добавьте этот код в main.py:

```python
fake_tasks_db = [
    {"task_name": "Task 1"},
    {"task_name": "Task 2"},
    {"task_name": "Task 3"},
    {"task_name": "Task 4"},
    {"task_name": "Task 5"},
    {"task_name": "Task 6"},
    {"task_name": "Task 7"},
    {"task_name": "Task 8"},
    {"task_name": "Task 9"},
    {"task_name": "Task 10"},
]

@app.get("/tasks")
async def get_tasks(limit: int = 10, offset: int = 0):
    return fake_tasks_db[offset : offset + limit]
```

### Разбор кода

1. **Декоратор:** @app.get("/tasks").  
    Заметьте, здесь **нет** фигурных скобок {}. Путь чистый.
    
2. **Функция:** async def get_tasks(limit: int = 10, offset: int = 0):.  
    FastAPI видит аргументы limit и offset. В пути их нет -> значит, будем искать их после знака вопроса ?.
    

### Значения по умолчанию

Обратите внимание на = 10 и = 0.  
Query-параметры почти всегда делают **необязательными**.

- Если пользователь перейдет просто по /tasks (без параметров), FastAPI подставит значения по умолчанию: limit=10, offset=0.
    
- Если мы не укажем значения по умолчанию (напишем просто limit: int), то параметр станет **обязательным**, и запрос без него вернет ошибку.
    

### Как это проверить?

Запустите сервер и попробуйте разные URL в браузере или Postman:

1. **GET** http://127.0.0.1:8000/tasks
    
    - Результат: Вернутся первые 10 задач (работают дефолтные значения).
        
2. **GET** http://127.0.0.1:8000/tasks?limit=3
    
    - Результат: Вернутся 3 задачи (limit изменился, offset остался 0).
        
3. **GET** http://127.0.0.1:8000/tasks?offset=5&limit=2
    
    - Результат: Вернутся задачи с 6-й по 7-ю (пропустили 5, взяли 2).
        

> **Автоматическая конвертация:**  
> Как и в случае с Path-параметрами, FastAPI сам превратит строчки из URL в числа int. Если вы напишете ?limit=abc, вы снова получите ошибку **422 Validation Error**.
