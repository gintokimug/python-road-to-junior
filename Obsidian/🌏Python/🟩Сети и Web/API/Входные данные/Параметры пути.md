# Шаг 1: Динамические URL (Параметры пути)

В прошлом модуле мы создали эндпоинт /, который всегда возвращает одно и то же сообщение "Hello World". Это **Статический URL**.

Но реальные приложения работают с конкретными ресурсами. Представьте, что вы делаете интернет-магазин, и у вас есть 10 000 товаров.  
Вы же не будете писать 10 000 функций вручную?

```python
# Так делать НЕЛЬЗЯ:
@app.get("/items/1")
...
@app.get("/items/2")
...
```

Вместо этого используются **Динамические URL**. Мы создаем один шаблон, который подходит под любой товар. Та часть адреса, которая меняется, называется **Параметром пути (Path Parameter)**.

### Синтаксис в FastAPI

Чтобы объявить часть URL как переменную, в FastAPI используются **фигурные скобки** {}.

```python
@app.get("/users/{user_id}")
async def read_user(user_id):
    return {"user_id": user_id}
```

### Как это работает?

Здесь работает простая магия сопоставления имен.

1. **В декораторе:** @app.get("/users/{user_id}")  
    Вы говорите FastAPI: "Если придет запрос типа /users/что-то-там, возьми это что-то-там и положи в переменную с именем user_id".
    
2. **В функции:** async def read_user(user_id):  
    Вы создаете аргумент функции с **точно таким же именем** (user_id).  
    FastAPI автоматически передаст значение из URL внутрь вашей функции.
    

> **Важно:** Имена в фигурных скобках и в аргументах функции должны совпадать буква в букву!

### Множественные параметры

Вы можете использовать несколько переменных в одном пути:

```python
@app.get("/users/{user_id}/tasks/{task_id}")
async def get_user_task(user_id, task_id):
    return {"user": user_id, "task": task_id}
```


# Шаг 2: Типизация параметров (Type Hints)

В предыдущем шаге мы научились принимать любые данные в URL. Но есть проблема: **URL — это всегда строка текста**.

Даже если вы напишете в браузере /users/100, ваше приложение получит строку "100".  
Если вы попытаетесь сделать математическую операцию (например, user_id + 1), Python выдаст ошибку, потому что нельзя складывать текст и числа.

Раньше разработчикам приходилось писать код так:
```python
# Старый, плохой способ (без FastAPI)
def get_user(user_id):
    try:
        clean_id = int(user_id) # Вручную превращаем в число
    except ValueError:
        return "Ошибка: id должен быть числом!"
    ...
```
FastAPI избавляет нас от этой рутины с помощью **Type Hints (Подсказок типов)**.
### Синтаксис

В Python подсказки типов пишутся через двоеточие после имени аргумента.  
Измените ваш код в main.py:
```python
@app.get("/users/{user_id}")
async def read_user(user_id: int):  # Добавили ": int"
    return {"user_id": user_id, "type": str(type(user_id))}
```
Добавив всего четыре символа (: int), мы заставили FastAPI делать две мощные вещи: **Конвертацию** и **Валидацию**.

### 1. Автоматическая конвертация (Data Conversion)

Теперь, когда вы делаете запрос /users/50, FastAPI видит, что вы ожидаете int.  
Он берет строку "50" из URL, превращает её в число 50 и только потом передает в вашу функцию.

Внутри функции переменная user_id теперь — настоящее целое число. Вы можете смело писать условия if user_id > 0 или математику.

### 2. Автоматическая валидация (Data Validation)

А что случится, если пользователь ошибется и напишет /users/alex?  
Ведь слово "alex" невозможно превратить в число.

FastAPI сам проверит это **до** запуска вашей функции.

1. Он увидит, что "alex" — это не int.
    
2. Он **не запустит** вашу функцию (код внутри не выполнится).
    
3. Он автоматически вернет клиенту понятную ошибку в формате JSON.
    

Попробуйте сделать запрос /users/alex через браузер или Postman. Вы увидите ответ:

```JS
{
  "detail": [
    {
      "loc": ["path", "user_id"],
      "msg": "value is not a valid integer",
      "type": "type_error.integer"
    }
  ]
}
```
- msg: "значение не является корректным целым числом".
    
- loc: ошибка произошла в параметре пути user_id.
### Разница между str и int

|   |   |   |   |
|---|---|---|---|
|Тип в коде|Запрос /items/123|Запрос /items/foo|Результат|
|item_id: str|Примет "123"|Примет "foo"|Принимает всё (как текст)|
|item_id: int|Примет 123 (число)|**Ошибка 422**|Принимает только цифры|
|item_id: float|Примет 123.0|**Ошибка 422**|Принимает дробные числа|

### Резюме

Используя стандартные типы Python (int, str, float, bool), вы получаете:

1. Защиту от некорректных данных.
    
2. Чистый код без ручных проверок isdigit().
    
3. Автоматическую документацию (в Swagger UI теперь будет написано, что user_id — это Integer).

# Шаг 3: Валидация типов и ошибка 422

Мы уже знаем, что если написать user_id: int, то FastAPI попытается превратить строку в число.  
Но что именно происходит «под капотом», когда пользователь отправляет буквы вместо цифр?

### Эксперимент: Попробуем сломать систему

Убедитесь, что у вас написан эндпоинт с типизацией:

```python
@app.get("/users/{user_id}")
async def read_user(user_id: int):
    return {"user_id": user_id}
```
### 1. Сервер не падает

Если бы вы писали на "чистом" Python без фреймворка и попытались сделать int("hello"), ваша программа бы вылетела с грохотом (исключение ValueError), а сервер бы остановился или вернул страшную ошибку **500 Internal Server Error**.

FastAPI работает как **щит**. Он перехватывает "плохие" данные до того, как они попадут в вашу функцию. Ваша функция read_user даже не запускается, поэтому сломать её невозможно.

### 2. Статус код 422

Посмотрите на статус ответа. Это не 400 и не 500.  
Это **422 Unprocessable Entity** (Необрабатываемый экземпляр).

Это фирменный статус FastAPI для ошибок валидации. Он говорит клиенту:

> "Я понял твой запрос, я вижу, куда ты стучишься, но данные, которые ты прислал, не соответствуют правилам (схеме)".

### 3. Структура ошибки

Давайте разберем JSON, который возвращается при ошибке. Он очень информативен для отладки.
```python
{
  "detail": [
    {
      "loc": ["path", "user_id"],
      "msg": "value is not a valid integer",
      "type": "type_error.integer"
    }
  ]
}
```
- **detail**: Список всех найденных ошибок (их может быть несколько сразу).
    
- **loc (Location)**: Самое важное поле. Оно показывает, **где** ошибка.
    
    - ["path", "user_id"] читается как: "Ищи ошибку в параметрах пути (path), в переменной user_id".
        
    - Если ошибка будет в теле запроса, там будет написано ["body", "field_name"].
        
- **msg (Message)**: Описание для человека. "Значение не является валидным целым числом".
    
- **type**: Технический код ошибки, который может использовать фронтенд для перевода ошибки на другие языки.
    

### Почему это круто?

Вам не нужно писать ни одного if или try-except, чтобы проверять типы данных.

- Если передали текст вместо числа — **422**.
    
- Если передали 3.14 вместо целого числа — **422**.
    
- Если забыли передать обязательный параметр — **422**.
    

Вы пишете только "счастливый путь" (happy path) — логику для правильных данных. О неправильных данных заботится FastAPI.


- Параметры запроса (Query) не пишутся в декораторе. FastAPI находит их сам по аргументам функции.
- В URL-строке они живут после знака вопроса `?` и разделяются значком `&`.
- Используются строго для фильтрации, поиска, сортировки и ограничения количества данных (`limit`, `skip`).
- Если не указать дефолтное значение (например, `limit: int`), параметр автоматически станет строго обязательным, и без него ссылка упадет в ошибку `422`



>[!info]
Ещё для закрепления:  
`async def get_tasks(limit: int = 10, offset: int = 0):`
>
FastAPI автоматически берет параметры из строки запроса, например:
>>
>- `/tasks?limit=5&offset=2` → limit=5, offset=2
>    
>
`limit` — сколько задач вернуть (по умолчанию 10)  
`offset` — сколько задач пропустить (по умолчанию 0)
>
`return fake_tasks_db[offset : offset + limit]`
>
Это **срез списка** (slice).
>
>- `fake_tasks_db[start : end]` берёт элементы с индекса `start` (включительно) до индекса `end` (не включая его).  
>    Например:
>    
>- `offset = 2`, `limit = 3` → берём `fake_tasks_db[2:5]` → элементы с индексами 2, 3, 4. 
>  
>
Так работает пагинация (постраничный вывод):
>
>- Страница 1: offset=0, limit=10 → задачи 1–10
>    
>- Страница 2: offset=10, limit=10 → задачи 11–20 (здесь их нет, вернётся пустой список)
>    
>
Примеры:
>
**Запрос:** `GET /tasks?limit=3&offset=4`  
→ вернёт `[{"task_name": "Task 5"}, {"task_name": "Task 6"}, {"task_name": "Task 7"}]`  
(потому что индексы: 4 → Task 5, 5 → Task 6, 6 → Task 7)
>
**Запрос:** `GET /tasks?limit=5&offset=3`  
→ вернёт `[{"task_name":"Task 4"},{"task_name":"Task 5"},{"task_name":"Task 6"},{"task_name":"Task 7"},{"task_name":"Task 8"}]`
>
(потому что индексы: 3 → Task 4, 4 → Task 5, 5 → Task 6, 6 → Task 7, 7 → Task 8)
>
**Без параметров:** `GET /tasks`  
→ `limit=10, offset=0` → вернёт все 10 задач.
