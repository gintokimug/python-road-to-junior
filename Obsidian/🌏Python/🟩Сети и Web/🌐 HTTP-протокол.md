
### 1. URL (Адрес)

Это адрес получателя. Он говорит серверу, **куда** именно мы стучимся.  
В URL https://google.com/search частью, которая интересна нам как бэкенд-разработчикам, является путь (path): /search.

В терминологии API конкретный адрес, по которому доступна какая-то функция, часто называют **Эндпоинт (Endpoint)** или «Ручка».

- /users — ручка для работы с пользователями.
    
- /tasks — ручка для работы с задачами.
    

### 2. HTTP Метод (Действие)

Если URL — это «куда», то Метод — это «что сделать». Это глагол, который указывает серверу на намерение клиента.

Самые популярные методы (мы будем использовать их постоянно):

- **GET** — **«Дай мне данные»**.
    
    - Самый частый метод. Используется, когда вы открываете страницы в браузере.
        
    - Пример: Получить список задач.
        
- **POST** — **«Прими данные»**.
    
    - Используется для создания чего-то нового.
        
    - Пример: Создать новую задачу.
        
- **PUT** — **«Обнови данные»**.
    
    - Полное изменение объекта.
        
- **DELETE** — **«Удали данные»**.
    

> **Важно:** FastAPI умеет различать методы. Если вы создадите эндпоинт только для GET /tasks, а клиент отправит POST /tasks, FastAPI автоматически ответит ошибкой «Method Not Allowed».

### 3. Заголовки (Headers)

Это служебная информация ("Метаданные"). Она пишется на "конверте" и нужна серверу, чтобы понять, как обрабатывать письмо, но не является самим содержимым письма.

Примеры заголовков:

- User-Agent: "Привет, я браузер Google Chrome" или "Привет, я мобильное приложение iPhone".
    
- Content-Type: "Я отправляю тебе данные в формате JSON".
    
- Authorization: "Вот мой секретный ключ, пусти меня".
    

### 4. Тело запроса (Body)

Это само содержимое письма. Данные, которые клиент хочет передать на сервер.

- У методов **GET** и **DELETE** тела обычно **нет** (мы просто просим что-то дать или удалить по адресу).
    
- У методов **POST** и **PUT** тело **есть**. Там лежат данные, которые нужно сохранить (например, текст новой задачи, цена товара, логин пользователя).
    

### Как это выглядит в реальности?

Если бы HTTP-запрос был текстом, он выглядел бы примерно так:

```http
POST /tasks HTTP/1.1
Host: my-api.com
Content-Type: application/json
User-Agent: Python-Client

{
  "title": "Купить молоко",
  "priority": "high"
}
```

**Разбор:**

1. POST — Метод (хочу создать).
    
2. /tasks — URL (в раздел задач).
    
3. Host, Content-Type — Заголовки (служебная инфо).
    
4. {...} в конце — Тело (сами данные).
